# 作業記録ツール（モック）

日中の作業をワンタップで記録し、業務後に日報用テキストを確認・コピーするためのツールです。
HTML・CSS・JavaScript だけで動き、サーバーや外部ライブラリは使いません。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | ツール本体。画面・デザイン（`<style>`）・動作（`<script>`）をすべて含みます |
| `作業記録データ.json`（任意の名前） | データファイル。初回に自分で作成します |
| `manifest.webmanifest`・`sw.js`・`icons/` | Web上に置いたときに、Android のホーム画面への追加とオフライン表示に使うファイル |
| `tests/e2e.js` | 確認用の自動テスト（Playwright）。利用には不要です |

パソコンで index.html を直接開いて使う場合、必要なのは `index.html` とデータファイルの2つだけです。
Web上（GitHub Pages）に置く場合は、`index.html`・`manifest.webmanifest`・`sw.js`・`icons/` を置きます。

## 起動方法（Chrome）

1. `index.html` をダブルクリックして Chrome で開きます。オフラインでも動きます。
2. 初回は画面上部の「⚠ データファイル未設定」の横にある **「新規作成」** を押し、データファイル（例：`作業記録データ.json`）の保存場所を選びます。すでにデータファイルがある場合は **「開く」** で選びます。
3. 以降は、記録するたびにデータファイルへ自動で上書き保存します。画面上部に「💾 ファイル名 に自動保存中（保存時刻）」と表示されます。

### 次回以降の起動
- `index.html` を開くと、前回のデータファイルに自動で再接続します。
- Chrome の設定によっては「再接続が必要です」と表示されます。**「再接続」** を押し、Chrome の確認で許可してください（「毎回許可する」を選ぶと次回から確認が出なくなります）。

### データファイルについて
- データファイルの作成・切り替え・接続解除は、「⚙ 設定」→「データファイル」からも行えます。
- ブラウザ内（localStorage）にも予備として同じ内容を保存しています。データファイルに保存できなかったときは画面上部に警告を表示し、再接続したときにブラウザ内の新しい内容をファイルへ書き込みます。
- 起動・再接続のときは、データファイルとブラウザ内のデータの保存日時を比べ、新しい方を使います（別のPCで同じファイルを更新した場合など）。
- 「既存のデータファイルを開く」では、現在のデータをファイルの内容で置き換える前に確認します。内容が正しくないファイルは開かず、ファイルも変更しません。
- 同じデータファイルを複数のPCで**同時に**使うと、後から保存した内容で上書きされます。同時には使わないでください。
- データファイルへの直接保存は Chrome（および Edge）の機能です。他のブラウザでは警告を表示し、ブラウザ内にのみ保存します。

## GitHub Pages で公開する

公開されるのはツール本体だけです。記録のデータは各自の端末やデータファイル（OneDrive など）に保存され、公開されません。

1. 公開用のリポジトリを用意します（GitHub Pages を無料で使うには**公開**リポジトリが必要です）。
   - このリポジトリを公開してよい場合：「Settings」→「General」→ 一番下の「Danger Zone」→「Change repository visibility」で Public にします。
   - 別に作る場合：個人アカウントで新しい Public リポジトリを作り、`index.html`・`manifest.webmanifest`・`sw.js`・`icons` フォルダをアップロードします。
2. そのリポジトリの「Settings」→「Pages」を開き、「Build and deployment」の Source を「Deploy from a branch」にします。ブランチ（例：`main`）とフォルダ「/ (root)」を選んで「Save」を押します。
3. 数分待つと `https://（アカウント名または組織名）.github.io/（リポジトリ名）/` で開けるようになります。

ツールを更新したときは、`sw.js` の `CACHE` の番号を上げてから公開してください。ネットにつながっている端末は、開いたときに最新版を読み込みます。

## パソコンと Android の行き来（OneDrive）

| 端末 | 使い方 |
|---|---|
| パソコン（Chrome） | 公開した URL を開き、「⚙ 設定」→「データファイル」で、普段使っている **OneDrive のフォルダ**の中にデータファイルを作成（または既存のファイルを開く）。以降は自動で保存され、OneDrive アプリがクラウドへ同期します。画面に戻ったときに、Android で更新された内容があれば読み込みます。 |
| Android（Chrome） | 公開した URL を開き、メニューの「ホーム画面に追加」（または「アプリをインストール」）でアイコンを置きます。データは端末の中に保存し、パソコンとは次の手作業でやり取りします。 |

Android での手順は次のとおりです。

1. 使い始めに「⚙ 設定」→「データファイル」→「データファイルを読み込む」を押し、OneDrive にあるデータファイルを選びます。
2. 記録はスマホの中に保存されます。記録画面の右上に「未共有の変更あり」と表示されます。
3. 使い終わったら「共有して保存」を押し、共有先で OneDrive を選んで、パソコンと同じフォルダに同じ名前で保存します。「業務終了」を押したときにも、保存するよう案内します。
4. パソコンで開くと、新しい方のデータが使われます。

注意点は次のとおりです。

- OneDrive に同じ名前のファイルがすでにあると、別の名前（「(1)」付きなど）で保存されることがあります。その場合は、パソコンの「既存のデータファイルを開く」でそのファイルを選び直してください。
- パソコンと Android で**同じ時間帯に両方で**記録すると、後から保存した方の内容になります。片方で記録を終えてから、もう片方で読み込んでください。
- Android でも読み込み時に、端末の方が新しく、まだ共有していない変更があるときは警告します。

この方法は、Microsoft 365 の設定なしで使えます。Android でも自動で同期したい場合は、Microsoft 365 へのアプリの登録（IT 管理者の作業）が必要です。

## 画面構成

画面上部のタブで切り替えます。

| タブ | 内容 |
|---|---|
| 記録 | 作業の計測（普段開いておく画面） |
| 日報 | 1日の記録の確認・修正と、日報テキストのコピー |
| ⚙ 設定 | 作業ボタン／顧客・案件／データファイル／書き出し・バックアップ |

データファイルの状態は、記録画面の右上に「💾 自動保存済み」と小さく表示します。再接続が必要なときなど問題があるときだけ、画面上部に警告とボタンを表示します。

## 使い方

### 記録画面
- 作業ボタンを押すと計測を開始します。別の作業ボタンを押すと、実行中の作業を終了して新しい作業を開始します（終了時刻と開始時刻は同じ時刻になり、途切れません）。
- 数字キー `1`〜`8` で、ボタンに表示されている作業を表示順に切り替えられます。文字の入力中は無効です。
- 顧客・案件・メモは任意です。入力した内容は実行中の記録に自動で保存されます。
- メモ欄は複数行で、Enter で改行できます。300文字程度を目安に入力でき、入力欄の下に文字数を表示します（300文字を超えても保存できますが、警告を表示します）。日報テキストでは、メモの改行は空白に置き換えて1行で表示します。作業を何も計測していないときに入力した内容は、次に開始する作業に使います。
- 「直前の作業に戻る」を押すと、1つ前の作業（休憩は除く）のカテゴリ・顧客・案件・メモを引き継いで新しい記録を開始します。
- 「休憩」は休憩として記録します。休憩は作業時間の合計と日報の明細に含みません。
- 「業務終了」を押すと、実行中の作業を終了して日報画面へ移動します。
- 前日以前の作業が計測中のまま残っていた場合は、起動時に終了時刻の入力を求めます。

### 顧客・案件の入力
- 入力欄にフォーカスすると候補を表示します。文字を入力すると部分一致で絞り込みます（大文字と小文字は区別しません）。候補は使用回数の多い順に並びます。
- `↑` `↓` で候補を移動、`Enter` で確定、`Esc` で閉じます。候補を選ばずに `Enter` を押すか、フォーカスを外すと、入力したまま確定します。
- 顧客を選ぶと、案件の候補をその顧客の案件に絞ります。顧客が未入力のときは全案件を顧客名付きで表示し、案件を選ぶと顧客も入ります。
- マスタにない名前を入力すると、「手入力のまま使う」「マスタに登録して使う」を選べます。未登録の顧客に案件を登録すると、顧客も同時に登録します。
- マスタに登録済みの顧客を選び直したとき、その顧客の案件でなければ案件欄を空にします（未登録の顧客を入力した場合は案件を残します）。

### 日報画面
- 「‹」「›」で前日・翌日へ移動し、日付欄で日付を選べます。今日以外を表示しているときは「今日に戻る」が出ます。
- 一番上の「日報テキストをコピー」でクリップボードにコピーします。
- 確認が必要な記録（顧客・案件・メモがすべて未入力の記録と、計測中の記録）があるときだけ「⚠ 確認が必要な記録」欄を表示します。「入力」「終了時刻」を押すと、その記録の入力欄が開きます。
- 記録は1件1行で表示します。「編集」を押した記録だけ、開始・終了時刻、カテゴリ、顧客、案件、メモの入力欄が開きます。「＋ 追加」で記録を追加でき、削除は確認してから行います。
- 時刻の重複や、終了時刻が開始時刻より前の記録には警告を表示します。
- 下にカテゴリ別の合計を横棒で表示します。

### 設定 ＞ 書き出し・バックアップ
- 日報で表示中の日、または期間を指定して、記録をCSVで書き出します（BOM付きUTF-8。列は 日付,開始,終了,分,カテゴリ,顧客,案件,メモ。休憩はカテゴリ「休憩」として出力）。
- 全データをJSONでバックアップする／JSONから復元する（復元前に内容を検証し、上書きを確認します）。

### 設定 ＞ 顧客・案件
- 顧客：追加、編集、非表示、並び順の変更（↑↓）ができます。顧客名を押すと、その顧客の案件を中央の列に表示します。
- 案件：選択中の顧客の案件を、追加、編集、非表示、並べ替えできます。
- 手入力された名前：記録にあってマスタにない名前を使用回数付きで表示します。「マスタに登録」するか、「既存にまとめる」で過去の記録の名前を既存のマスタ名に書き換えます（対象件数を確認してから実行します）。
- マスタ名を編集した場合は、過去の記録にも反映するかどうかを選べます。
- 非表示にした顧客・案件は候補に出ませんが、過去の記録には残ります。
- CSV（`顧客名,案件名`。案件名は空欄でも可）を取り込み・書き出しできます。取り込みは UTF-8 と Shift_JIS に対応し、重複は取り込みません。先頭行が「顧客名」で始まる場合は見出し行として読み飛ばします。書き出しには非表示の項目は含みません。

### 設定 ＞ 作業ボタン
- 作業名の変更、追加、削除、並べ替え（↑↓）ができます。変更は右のプレビューと記録画面にすぐ反映されます。
- 一覧に過去30日の使用回数（その作業を記録した回数）を表示します。「よく使う順に並べ替え」を押したときだけ、回数の多い順に並べ替えます（回数が同じ場合は今の順番のまま）。
- 作業が8個までのときは、すべて記録画面にボタンで表示します。9個以上のときは、先頭7個をボタンで表示し、8個目の位置に「他の作業」ボタンを置きます。
- 作業はIDで管理するため、名前を変更しても同じ作業として集計し、過去の日報も新しい名前で表示します。削除した作業は選択肢から外れるだけで、過去の記録には削除時の名前で残ります。実行中の作業は削除できません。

## 日報書式の変更箇所

日報テキストは `index.html` の `<script>` の先頭近くにある **`formatDailyReport(report)`** 関数だけで作っています（「日報の書式（★書式を変更するときはこの関数だけを書き換える）」というコメントが目印です）。書式を変えるときは、この関数を書き換えるか差し替えてください。

関数が受け取る `report` の内容は次のとおりです（集計は `buildReportData()` で行います）。

```js
{
  date: '2026-11-03',
  lines: [ // 開始時刻順。休憩は含まない
    { start: '09:00', end: '09:25', running: false,
      category: '電話対応', customer: 'A社', project: '保守サポート', memo: '納期確認',
      minutes: 25 },
  ],
  totalMinutes: 450,            // 丸める前の合計（分）
  categories: [                 // 時間の長い順
    { name: '資料作成', minutes: 185 },
  ],
}
```

- 時間は記録ごとに分単位で集計しています（表示される HH:MM の差）。
- 0.1h 単位への四捨五入は `toHours(minutes)` で行います。全体の合計は丸める前の `totalMinutes` から計算します。
- 計測中の記録は終了を「計測中」と表示し、現在時刻までの分数を集計に含めます。

## データ形式

データファイルと localStorage（キー `sagyokanri:data`）に、同じ JSON 形式で保存します。JSONバックアップも同じ形式です。

- `version`：バージョン番号（現在は `2`。version 1 で保存されたデータは読み込み時に自動で変換します）
- `savedAt`：最終保存日時（データファイルとブラウザ内のどちらが新しいかの判定に使います）

項目を追加するときは `DATA_VERSION` を上げ、`migrate()` に古い版からの変換処理を追加してください。
保存に失敗した場合は、画面の上部にエラーを表示します。

## 確認用テスト

Playwright が使える環境で次を実行します。

```sh
node tests/e2e.js
```

作業の切り替え、再読み込み後の計測継続、データファイルへの自動保存と再接続、Android の手動でのやり取り、Web上でのオフライン表示、休憩の扱い、コンボボックス、名前の統合、作業名変更の合算、並べ替えと数字キー、8個/9個のボタン表示、文字入力中の数字キー、日報の合計、CSV・JSONの入出力などを、実際のブラウザ操作で確認します。
