# 作業記録ツール（モック）

日中の作業をワンタップで記録し、業務後に日報用テキストを確認・コピーするためのツールです。
HTML・CSS・JavaScript だけで動き、サーバーや外部ライブラリは使いません。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | 画面の構成（4画面を1ページで切り替え） |
| `style.css` | デザイン（ダークテーマ） |
| `app.js` | 動作・データ保存・日報の書式 |
| `tests/e2e.js` | 確認用の自動テスト（Playwright） |

## 起動方法

`index.html` をダブルクリックしてブラウザで開くだけで使えます。オフラインでも動きます。
データはブラウザの localStorage に保存されます。そのため、**同じブラウザで同じファイルを開いたときだけ**データが引き継がれます。

## 使い方

### 記録画面
- 作業ボタンを押すと計測を開始します。別の作業ボタンを押すと、実行中の作業を終了して新しい作業を開始します（終了時刻と開始時刻は同じ時刻になり、途切れません）。
- 数字キー `1`〜`8` で、ボタンに表示されている作業を表示順に切り替えられます。文字の入力中は無効です。
- 顧客・案件・メモは任意です。入力した内容は実行中の記録に自動で保存されます。作業を何も計測していないときに入力した内容は、次に開始する作業に使います。
- 「直前の作業に戻る」を押すと、1つ前の作業（休憩は除く）のカテゴリ・顧客・案件・メモを引き継いで新しい記録を開始します。
- 「休憩」は休憩として記録します。休憩は作業時間の合計と日報の明細に含みません。
- 「業務終了」を押すと、実行中の作業を終了して日報画面へ移動します。
- 前日以前の作業が計測中のまま残っていた場合は、起動時に終了時刻の入力を求めます。

### 顧客・案件の入力
- 入力欄にフォーカスすると候補を表示します。文字を入力すると部分一致で絞り込みます（大文字と小文字は区別しません）。候補は使用回数の多い順に並びます。
- `↑` `↓` で候補を移動、`Enter` で確定、`Esc` で閉じます。候補を選ばずに `Enter` を押すか、フォーカスを外すと、入力したまま確定します。
- 顧客を選ぶと、案件の候補をその顧客の案件に絞ります。顧客が未入力のときは全案件を顧客名付きで表示し、案件を選ぶと顧客も入ります。
- マスタにない名前を入力すると、「手入力のまま使う」「マスタに登録して使う」を選べます。未登録の顧客に案件を登録すると、顧客も同時に登録します。
- マスタに登録済みの顧客を選び直したとき、その顧客の案件でなければ案件欄を空にします（未登録の顧客を入力した場合は案件を残します）。

### 日報画面
- 前日・翌日への移動や日付の選択ができます。
- 各記録の開始・終了時刻、カテゴリ、顧客、案件、メモをその場で編集できます。記録の追加と削除（確認あり）もできます。
- 時刻の重複や、終了時刻が開始時刻より前の記録には警告を表示します。
- 「登録前の確認」に、顧客・案件・メモがすべて未入力の記録と計測中の記録を表示します。その場で修正できます。
- 「日報テキストをコピー」でクリップボードにコピーします。
- 「データの書き出しと復元」から次の操作ができます。
  - 表示中の日付または期間の記録をCSVで書き出す（BOM付きUTF-8。列は 日付,開始,終了,分,カテゴリ,顧客,案件,メモ。休憩はカテゴリ「休憩」として出力）
  - 全データをJSONでバックアップする／JSONから復元する（復元前に内容を検証し、上書きを確認します）

### マスタ管理画面
- 顧客：追加、編集、非表示、並び順の変更（↑↓）ができます。顧客名を押すと、その顧客の案件を中央の列に表示します。
- 案件：選択中の顧客の案件を、追加、編集、非表示、並べ替えできます。
- 手入力された名前：記録にあってマスタにない名前を使用回数付きで表示します。「マスタに登録」するか、「既存にまとめる」で過去の記録の名前を既存のマスタ名に書き換えます（対象件数を確認してから実行します）。
- マスタ名を編集した場合は、過去の記録にも反映するかどうかを選べます。
- 非表示にした顧客・案件は候補に出ませんが、過去の記録には残ります。
- CSV（`顧客名,案件名`。案件名は空欄でも可）を取り込み・書き出しできます。取り込みは UTF-8 と Shift_JIS に対応し、重複は取り込みません。先頭行が「顧客名」で始まる場合は見出し行として読み飛ばします。書き出しには非表示の項目は含みません。

### 作業ボタン設定画面
- 作業名の変更、追加、削除、並べ替え（↑↓）ができます。変更は右のプレビューと記録画面にすぐ反映されます。
- 一覧に過去30日の使用回数（その作業を記録した回数）を表示します。「よく使う順に並べ替え」を押したときだけ、回数の多い順に並べ替えます（回数が同じ場合は今の順番のまま）。
- 作業が8個までのときは、すべて記録画面にボタンで表示します。9個以上のときは、先頭7個をボタンで表示し、8個目の位置に「他の作業」ボタンを置きます。
- 作業はIDで管理するため、名前を変更しても同じ作業として集計し、過去の日報も新しい名前で表示します。削除した作業は選択肢から外れるだけで、過去の記録には削除時の名前で残ります。実行中の作業は削除できません。

## 日報書式の変更箇所

日報テキストは `app.js` の先頭近くにある **`formatDailyReport(report)`** 関数だけで作っています。書式を変えるときは、この関数を書き換えるか差し替えてください。

関数が受け取る `report` の内容は次のとおりです（集計は `buildReportData()` で行います）。

```js
{
  date: '2026-11-03',
  lines: [ // 開始時刻順。休憩は含まない
    { start: '09:00', end: '09:25', running: false,
      category: '電話対応', customer: 'A社', project: '保守サポート', memo: '納期確認',
      minutes: 25 },
  ],
  totalMinutes: 450,            // 丸める前の合計（分）
  categories: [                 // 時間の長い順
    { name: '資料作成', minutes: 185 },
  ],
}
```

- 時間は記録ごとに分単位で集計しています（表示される HH:MM の差）。
- 0.1h 単位への四捨五入は `toHours(minutes)` で行います。全体の合計は丸める前の `totalMinutes` から計算します。
- 計測中の記録は終了を「計測中」と表示し、現在時刻までの分数を集計に含めます。

## データ形式

localStorage のキー `sagyokanri:data` に JSON で保存します。`version` にバージョン番号を持ちます（現在は `1`）。
項目を追加するときは `app.js` の `DATA_VERSION` を上げ、`migrate()` に古い版からの変換処理を追加してください。
保存に失敗した場合は、画面の上部にエラーを表示します。

## 確認用テスト

Playwright が使える環境で次を実行します。

```sh
node tests/e2e.js
```

作業の切り替え、再読み込み後の計測継続、休憩の扱い、コンボボックス、名前の統合、作業名変更の合算、並べ替えと数字キー、8個/9個のボタン表示、文字入力中の数字キー、日報の合計、CSV・JSONの入出力などを、実際のブラウザ操作で確認します。
